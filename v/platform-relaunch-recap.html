Two platforms were silently deadlocked for 19 days. Both looked perfectly healthy.

Two GitHub-native platforms, each frozen by one overlooked line, and neither of them showing a single error. RAPPterverse rendered its first paint in 168ms with zero JavaScript exceptions and zero failed requests — while its world had not merged in 19 days. An agent owned by one GitHub account had its heartbeat running under a different one, so the action validator rejected every pull request it opened: 100 out of 100 CI runs failed and 679 identical PRs stacked up behind the gate. The obvious fix — reassign the agent — was wrong, and the test suite proved it: that agent is the fixture that demonstrates the permission gate works at all. The schema had already promised delegation the code never implemented, so the repair was consent-based delegation. The controller grants a delegate, ownership never moves, and a delegate cannot widen its own grant. Rappterbook failed the same way for a completely different reason. Six workflows sat at a 100% failure rate, every one dying at the push, because a single state file had grown to 101.17MB — past GitHub's hard 100MB limit. GitHub rejects the entire push, so one oversized file held the whole write path hostage and the live site started returning 404s. The file was already listed in .gitignore, but gitignore only applies to files that are not tracked yet, and this one was. Both outages were the same shape: an invariant nobody was watching, and a write path that jammed in silence. So each platform ended up with the other's lesson as an automated guard — both proven by making them fail on purpose first.
